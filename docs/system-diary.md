## Phase 0 review amendments | 2026-10-27

The user's eight-point review supersedes the initial demonstration's read-to-
proposal behavior. The constitution and section 13 remain unchanged; no
prototype file or skill screen is part of this revision.

1. Plan tools render as structured JSON, not object coercions. Review buttons
   require `proposed`; UI copy uses colons rather than em dashes.
2. Ask/read episodes end at `present`, without `learn`, business proposals or
   proposal links. Only an explicit draft tool may propose. A source-injection
   warning is a persisted safety Task, visible in the existing Review inbox,
   not a business Proposal.
3. The semantic identity is type, target, field, original value and observation.
   A serialized transaction reuses proposed/accepted/edited/confirmed records
   and creates an Episode-to-Proposal link. Historical duplicate records are
   preserved; they are not deleted or silently rewritten.
4. Builder/auditor Review and Outbox access is read-only. Only analyst/partner
   can accept facts. Confirmation is restricted to partner/analyst/ops and the
   current Firm.settings allowlist. Guards, optimistic concurrency and SQL
   triggers enforce the same matrix independently of disabled buttons.
5. Five named critic checks, their notes and the overall verdict are persisted
   as JSON and shown in traces. Legacy aggregate verdicts retain an explicit
   historical-detail warning rather than fabricated per-check evidence.
6. Every mock returns deterministic positive token usage and unit cost. Budget
   allowance checks, synthetic charging and the gateway audit row share one
   serialized transaction. Exhaustion preserves a partial draft as stopped,
   stops the Episode and creates a human-review question and Task. A stopped
   draft is a system state, not a human approval.
7. Snapshot mode verifies ledger/evidence integrity without a provider call.
   Re-execution regenerates outputs from accepted input snapshots through the
   mock gateway, compares gateway and Step output hashes with the ledger and
   audits its synthetic usage separately. Draft side effects are dry-run
   projections, never repeated. A changed current proposal state is reported
   as a comparison mismatch. Old episodes lacking input snapshots explicitly
   report that re-execution is unavailable.
8. The browser verifies only on request. A persisted verified hash and sequence
   support incremental tail verification; a separate full integrity mode
   remains available. Server instrumentation arms an idempotent nightly job at
   02:00 UTC. It runs while the server process is running; there is no external
   webhook or claim that an in-process timer runs while the app is stopped.

**Verification:** regression tests cover all eight amendments, positive
synthetic charges, stopped-draft retention, role sequences, concurrent
idempotency, input-change detection, both replay modes and incremental/nightly
verification. The complete current output is generated by `npm test`.

**Boundary:** no mail client, webhook, deletion endpoint, live adapter or
administrator bypass. No Prompt 1.
