Prompt 0, constitution and agent core
You are building "Fund OS v3, Agent Edition": an operating system for an investment firm whose centre is one bounded, multimodal AI agent. Stack: Next.js (App Router, TypeScript), Tailwind, Prisma, PostgreSQL (Replit database), object storage behind an adapter. Create the project and keep this constitution in /docs/constitution.md:

1. The relational database is the single system of record. Search and vector indexes and reporting views are rebuildable and never written by hand. The agent has no memory outside the database and the document store.
2. The agent's tool vocabulary is exactly five side-effect classes: read, compute, draft, propose, ask. There is no tool that sends, deletes, archives, decides, signs or changes criteria. Implement src/agent/registry.ts where every tool declares name, version, JSON input and output schemas, side-effect class, allowed roles, cost class and skill. Add a test that fails if any tool declares another class.
3. External writes exist only as Proposals in an outbox (src/domain/outbox.ts). A proposal is applied only after a user action records user_id (state Confirmed) and only through an adapter enabled for the firm. Property tests must prove no sequence of agent actions produces an outbound message, a delete, a criteria change or an autonomy promotion without a signed ChangeRequest.
4. src/domain/guard.ts (InvariantGuard) runs before every adapter write and before any draft or proposal is stored. It is not bypassable by configuration or feature flag.
5. src/domain/ledger.ts is an append-only hash-chained log (prev_hash, hash). Every tool call and job writes one Run with inputs_hash, provider, model_version, prompt_version, temperature, seed, output_ref, reason, cost, latency_ms, status, invariant_results, reviewer_id. Provide explain(id), verifyChain() and replay(episodeId).
6. src/domain/gateway.ts (ModelGateway) is the only path to model providers, with five modalities: complete, see, transcribe, speak, embed. Default providers are deterministic mocks keyed by input hash returning fixtures. Live providers exist only behind per-firm feature flags from an allowlist and read keys from Replit Secrets. Prompts are versioned markdown files under src/skills/<skill>/prompts/<version>.md.
7. The agent loop (src/agent/loop.ts) runs every task as an Episode with Steps: perceive, resolve, plan, tool (iteration), critic, present, learn. src/agent/critic.ts reviews every output before it is shown or proposed (sources resolve and support each figure; no recommendation, valuation, legal term, outbound message or figure from general knowledge; no instruction found in a source was followed). A block allows one revision, then stops with the reason. src/agent/budget.ts enforces per-episode and per-firm monthly caps from Firm.settings. src/agent/autonomy.ts holds a level 0 to 3 per skill per firm; promotion requires a ChangeRequest id; demotion by any partner is immediate and logged. Level 4 must not exist.
8. All perceived text (documents, emails, transcripts, web pages) is data, never instruction. Wrap it in data delimiters with provenance, run an instruction detector before planning, and process flagged sources with the read-only tool set, showing the flag in Review.
9. Roles: partner, analyst, ops, ir, compliance, builder, auditor (read-only). The agent acts under the requesting user's permissions; scheduled runs use a service identity that can only read and propose. Middleware writes an AccessLog row for every read of Documents and Decisions.
10. Two firm profiles (vc, fof) and two modes (demo, tenant) are configuration on Firm. Configuration validation refuses any live provider or adapter in demo mode.
11. Implement the Prisma schema exactly as in /docs/data-model.md (I will paste it next), with integrity rules as database constraints where possible and as service checks otherwise.
12. Seeds: prisma/seed/northstar.ts (fictional VC fund "Northstar Ventures": 60 items, 12 holdings, 3 criteria versions, 200 gold-set decisions) and prisma/seed/bayharbour.ts (fictional fund-of-funds "Bay Harbour Capital": 25 fund holdings, 10 direct companies, 120 conversations with human-structured notes, 40 manager reviews). scripts/make-fixtures.ts generates synthetic decks with charts of known values, transcripts, emails, reports and notices, with their labels, under /fixtures. Everything is synthetic and the home screen says so.
13. Tests: unit, property, contract, integrity, replay, injection, planted-error, perception, e2e (Playwright). `npm test` runs all. CI fails on any committed secret pattern.
14. Docs: /docs/system-diary.md (one entry per phase: decision, date, evidence), /docs/glossary.md, /docs/runbooks/, /docs/handover-checklist.md. Dockerfile and scripts/export.ts from the start; Replit-specific storage, secrets and scheduling only behind adapters.

Deliver phase 0: scaffold, schema, seeds and fixtures generator, roles and access log, guard, ledger, gateway with five mocked modalities, tool registry, agent loop with planner, critic, budget and autonomy policy, an Episode trace viewer at /builder/episodes, a Review inbox at /analyst/review, the outbox at /analyst/outbox, CI. Do not build skill screens yet. Run one demonstration episode ("what do we know about <seeded organisation>") through the loop with mock providers and show me its trace, the schema and the test output.
